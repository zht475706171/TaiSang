## 关键质疑与调整（泰哥多次 push back，逼出真正定位）

### 质疑 1："普通 API 或 Claude 也能做吧？"
→ 引出三层护城河：大 repo 装不下（硬约束）/ 主动追踪调用链（Agent 循环）/ 离线地图是资产（复用壁垒）
→ 加了 eval set 评测集 + trace_call_chain 显式工具

### 质疑 2："跟 Claude Code + 详细 prompt 比有差距吗？"
→ 承认小 repo + 单跳场景差距小，但大 repo / 重复问答 / 确定性输出 / 垂直 prompt 深度上有差距
→ 定位调整："垂直场景的量化优势"，非 Claude Code 竞品

### 质疑 3（最关键）："Claude Code 加 CLAUDE.md + INDEX 索引不就行了？类似 claude-learn 那个项目"
→ 看了 claude-learn 项目（D:/GoProject/claude-learn/），确认泰哥用 Claude Code + 手写笔记花半个月读完 51 万行 Claude Code 源码
→ 正面承认：个人 + 单 repo + 高手驱动场景下，Claude Code + CLAUDE.md 确实够用
→ 项目定位最终版锁定："把 Claude Code + CLAUDE.md 高手玩法自动化/结构化/团队化/产品化"
→ 四大差距：3分钟vs半个月 / 调用图查询vs笔记推理 / 团队共享vs个人笔记 / 可评测vs体感
→ claude-learn 项目反转为 Agent 项目的前传故事，面试叙事自洽且强大

## §3 三个具体调整
