## 关键技术点(本轮新学到)

### 1. with-close 只 flush 不 fsync
- `with open(...) as f: f.write(line)` 退出时自动 close → flush → 数据进 OS page cache
- 进程崩溃不丢,但**断电/蓝屏仍丢**(page cache 没刷到硬盘扇区)
- 必须加 `f.flush(); os.fsync(f.fileno())` 才真正持久化
- `write_meta` 还要 fsync 父目录(Linux): `os.open(dir, O_RDONLY) + os.fsync(fd)`,Windows NTFS 不需要

### 2. setLogRecordFactory 比 addFilter 更可靠
- filter 加在 logger 上时,handler 仍可能 format 未补字段的 record
- RecordFactory 在 record 构造时就补字段,所有 handler 都能拿到
- 用于给所有 LogRecord 自动补 trace_id/span_id 字段

### 3. contextvars 不跨线程
- `threading.Thread` 不会自动 copy 父线程的 contextvar(除非显式用 `contextvars.copy_context().run()`)
- ThreadPoolExecutor 的工作线程看不到主线程 set 之后的 contextvar
- 跨 executor 必须**显式 set**: `token = trace_id_var.set(trace_id); try: ...; finally: trace_id_var.reset(token)`
- app.py `_run_next` 用这个 pattern 把 trace_id 传进 executor 线程

### 4. span() 的 name 参数和 kwarg 冲突
- `with span("tool", name=name)` 会报 `span() got multiple values for argument 'name'`
- 改用 `tool_name=name` 避免冲突(回归测试 `test_span_tool_name_field_not_conflicting` 覆盖)

### 5. contextvars Token reset 重复调用抛 RuntimeError
- `span_id_var.reset(token)` 第二次调用抛 `RuntimeError: Token has already been used once`
- 不是 ValueError/LookupError
- `end_span` 的 except 要加 RuntimeError: `except (ValueError, LookupError, RuntimeError): pass`

### 6. MockLLM 没 model 属性
- `service.py` 里 `with span("LLM call", model=self.llm.model, ...)` 在 MockLLM 测试中挂
- 改用 `getattr(self.llm, "model", "-")` 兜底

### 7. generator + span contextmanager
- `with span(...)` 包整个 try-except(而不是只包 generator 创建),generator 在 with 内迭代完
- with 退出时 end_span 记 duration,异常路径也 finally end
- 缩进调整用脚本批量 +4 空格(`for i in range(start, end): lines[i] = '    ' + lines[i]`)

### 8. 测试 conftest.py 设环境变量
- 项目之前没有 conftest.py,这次新建
- 顶层 `os.environ.setdefault("TAISANG_NO_FILE_LOG", "1")` 早于任何 import
- 避免 pytest 跑测试时落盘污染开发者家目录

## Pre-existing bug(已修复,commit 0055722)
- `tests/unit/test_agent_tool.py::test_make_child_llm_uses_subagent_when_enabled`
- `tests/unit/test_agent_tool.py::test_make_child_llm_allows_empty_api_key`
- 单独跑这两个 → 过;跑全量 → 挂,AssertionError: `isinstance(<MockLLM>, LLMClient)` 失败
- **根因**:`tests/integration/test_agent_e2e.py` 6 个测试的 finally 把 `at_mod._make_child_llm` 设成 `lambda parent_llm: parent_llm`(返回 parent_llm),**而不是恢复成原函数**。e2e 跑完后,后续 test_make_child_llm_* 调 `_make_child_llm(parent_llm)` 直接拿到 MockLLM,isinstance 失败
- **修法**:每个替换前保存 `original_make = at_mod._make_child_llm`,finally 恢复 `at_mod._make_child_llm = original_make`,对齐 test_agent_tool.py 已有的正确模式
- **教训**:`monkeypatch.setattr` 自动 cleanup,但手动 `module.attr = ...` 必须在 finally 里恢复成**保存的原值**,不能恢复成"看起来等价的 lambda"——因为原值可能是别的测试已经替换过的(虽然这里是函数本体)

## trace 体验
用户报 bug 时:
1. 看到 run_error 卡片
2. 点「复制 trace_id」按钮 → toast 提示「已复制」
3. 贴给开发者
4. 开发者 `grep <trace_id> ~/.taisang/logs/taisang.log` 一秒还原整个 turn:
   - 哪个 turn 开始
   - 调了哪些 LLM(mode=stream, step=N, model, duration)
   - 调了哪些工具(tool_name=read_file/bash 等, duration)
   - 哪一步失败

## Docker 踩坑(本轮新学到)

### 1. daemon.json 的 proxies 段 Docker Desktop 不吃
- 加 `"proxies": {"http-proxy":...}` 到 `~/.docker/daemon.json` 后 Docker Desktop 起不来
- 这是 dockerd 新特性(Docker 25+),Docker Desktop 不一定读这个字段
- **正确做法**:Docker Desktop GUI Settings → Resources → Proxies,或者 Settings → Docker Engine 加 `registry-mirrors`
- 误改后回滚 daemon.json + 重启 Docker Desktop 才恢复

### 2. registry-mirrors 是国内拉镜像的正解
- `~/.docker/daemon.json` 加 `"registry-mirrors": ["https://docker.1ms.run", ...]`
- Docker Desktop GUI Settings → Docker Engine 也能编辑同一个文件
- 重启后 `docker info` 能看到 Registry Mirrors 段
- 拉镜像走 mirror,docker.io/auth 不再被墙

### 3. VOLUME 声明的匿名 volume 权限坑
- Dockerfile 里 `VOLUME ["/home/taisang/.taisang"]` 后,Docker 用匿名 volume 挂这里
- 匿名 volume 默认 owner 是 root,容器 taisang 用户 (uid 1000) 写不进去
- **修法**:`USER taisang` 之前 `mkdir -p /home/taisang/.taisang/{sessions,logs} && chown -R taisang:taisang /home/taisang`
- 匿名 volume 第一次挂时从镜像目录继承权限

### 4. vite outDir 相对路径
- `vite.config.ts` 里 `outDir: '../static'` 相对 vite 配置文件所在目录
- frontend COPY 到 `/build/`,所以 `../static` = `/static`(不是 `/build/static`)
- Dockerfile `COPY --from=frontend-builder /static/ ./...` 才对

### 5. pip install 顺序
- `USER taisang` 之前 pip install 是 root 装系统级,正常
- `USER taisang` 之后 WORKDIR 切到用户目录,容器进程是非 root
- pip warning "Running pip as root" 可以忽略(我们是有意为之)
